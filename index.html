Hydroponics AI System

STEAM Research Grant DFRobot Hardware Sponsored
Hardware Schema

An industrial IoT automation platform applying Reinforcement Learning (RL) frameworks to soil-free smart urban farming. Funded by the Ministry of Education, Science and Technology under the STEAM Grant with hardware telemetry equipment sponsored directly by global robotics manufacturer DFRobot.

Embedded C/C++ TensorFlow Core PyTorch RL OpenCV Matrix ESP32 SoC Raspberry Pi Arduino Drivers MQTT Protocol WebSockets FastAPI Backend Flutter Dashboard Gymnasium LiveKit Video Stream

🔌 How DFRobot Became Our Hardware Partner

I took the initiative to reach out directly to DFRobot via email, presenting our research vision for the Hydroponics AI system and explaining how their precision industrial instrumentation could accelerate our work. After reviewing our project proposal and STEAM grant selection, DFRobot officially came on board as a hardware sponsor — gifting us essential electronic components including pH probes, EC sensors, temperature/humidity modules, and automated telemetry actuators. Their support transformed our sensor array from theoretical designs into a fully functional, real-time edge processing data pipeline.

What I Engineered

  • Programmed the embedded control layer on ESP32 and Raspberry Pi to interface with pH, EC, temperature, and humidity sensors — using DFRobot's gifted hardware components for the sensor array
  • Implemented sensor data acquisition and actuator control to manage pumps and nutrient dosing mechanisms via MQTT
  • Developed the backend infrastructure for the computer vision pipeline, enabling image uploads and AI model inference
  • Developed a FastAPI backend with MQTT and WebSocket support for real-time device monitoring and automation
  • Integrated LiveKit for real-time video streaming to enable live monitoring of plant growth
  • Built a Flutter mobile application for monitoring sensor data, live streams, and remote control
  • Deployed the system on a local edge server to support real-time processing and device communication
  • The project proposal was selected and funded by STEAM, with hardware components gifted by DFRobot to support research in AI-powered sustainable agriculture

Self-Hosted Public Cloud Infrastructure

Bare-Metal Hardware Stack Semester Project — Tiffin Backend

How do you avoid expensive public cloud bills while keeping full low-level systems control? In 2022, I architected, built, and provisioned an independent bare-metal server node from scratch and configured it to be publicly accessible from the open internet. This custom hardware rig hosted the production data endpoints, security rules, and real-time transaction pipelines for the Like Tiffin mobile application ecosystem — proving that a student-built infrastructure could reliably serve real users without relying on AWS, GCP, or Azure.

Bare-Metal Linux Architecture Public IP Networking Reverse Proxy Routing Secure SSH Layer Node.js Daemon Processing Hardware System Maintenance

Infrastructure Engineering Steps

  • Assembled the standalone server hardware, managing cooling limits and computing power requirements
  • Configured core Linux network settings, static IP routers, and network firewalls to allow incoming traffic safely
  • Set up reverse proxy configurations to manage domain handling and enforce SSL encryption layers
  • Maintained perfect database and API uptime on raw physical hardware to reliably serve mobile clients under pressure
04

AIHPC — High-Performance Computing Cluster

KU Department of AI

In 2025, I led an intensive system orchestration initiative within Kathmandu University's Department of AI to build a dedicated high-performance computing cluster (AIHPC). The project involved configuring Kubernetes containers for scaling distributed worker loads and establishing HAProxy layers to direct load balancing models across system networks.

Kubernetes (K8s) HAProxy Load Balancing NVIDIA RTX 3080Ti Docker Containers Linux Administration GPU Cluster Topology

Engineering Post-Mortem: Why It Failed

  • The hardware environment was limited because consumer-grade NVIDIA GeForce RTX 3080Ti GPUs lack hardware-level architecture partitioning (Multi-Instance GPU / MIG)
  • This constraint prevented stable multi-tenant GPU virtualization across the cluster
  • Localized technical team knowledge scaling boundaries (skill issues) further compounded the hardware limitations
  • The project provided deep insight into the practical boundaries between enterprise grid computing systems and consumer accelerator units
